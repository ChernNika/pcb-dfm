# Плагин KiCad «Проверка технологичности (DFM)»

Кнопка в редакторе плат KiCad 10: страница настроек в браузере, проверка открытой платы правилами A1, A3, A5, A7
и B1 (гибрид «формула клина + нейросеть») и отчёт; кнопка «Показать в KiCad» у находки выделяет её объекты на
плате, «Проверить снова» — перепроверяет плату после правок.

## Установка

```powershell
python -m dfm plugin-install          # из окружения, где установлен пакет dfm
```

Копирует эту папку в `Документы\KiCad\10.0\plugins\ru.dfm.check` и пишет `config.json` с путём
к интерпретатору (`python`), папкой отчётов (`reports`), папками своих профилей завода (`profiles_dirs`,
например `["C:/Профили"]` — все `.toml` из них появятся в списке) и дополнительными ключами `check`
(`extra_args`). Последний выбор на странице настроек хранится там же (`last`); при переустановке
сохраняются все прежние ключи `config.json`, кроме `python`; испорченный `config.json` не заменяется молча —
установка останавливается с сообщением. Папка назначения очищается, только если она пуста
или в ней `plugin.json` этого плагина (`ru.dfm.check`); иначе (например, `--dest` указывает на «Документы»)
установка отказывается и ничего не удаляет. Папка отчётов внутри папки плагина (и папки на пути к ней)
при переустановке не удаляется.

В KiCad: **Настройки → Плагины → «Включить сервер IPC API»**, перезапустить KiCad. В редакторе
плат на панели появится кнопка. При первом нажатии KiCad создаёт окружение плагина и ставит
`kicad-python` (нужен интернет, один раз).

## Как работает

1. Локальный сервер (только 127.0.0.1, случайный порт) и браузер — страница настроек: профиль завода
   (условный, «открытые данные», «лаборатория МАИ» и свои), классы, процесс травления B1 (С / О / З или свой) и способ оценки
   (гибрид, формула клина, таблица документа). Список берётся у пакета: `python -m dfm profiles`.
2. «Проверить»: плата берётся из редактора (`get_as_string`) — с несохранёнными правками платы; файл
   платы не перезаписывается. Рядом во временную папку кладутся `.kicad_pro` и `.kicad_dru` проекта — они
   читаются с диска, так что несохранённые изменения правил проекта (настройки платы, правила DRC) в проверку
   не попадают: сохраните проект перед проверкой.
   `python -m dfm check … --profile … --classes … --set b1.process=… --set b1.method=…` в окружении `dfm`
   (тяжёлые библиотеки — shapely, scipy — в окружение плагина не ставятся). Сервер принимает только
   значения из списков и только JSON-запрос. Чужая веб-страница не запустит проверку и не выделит объекты:
   запросы с Host, отличным от `127.0.0.1:<порт>` / `localhost:<порт>`, отклоняются (защита от DNS rebinding),
   а `/start` и `/select` требуют заголовок `X-DFM-Token` — случайный ключ сеанса, который есть только
   в страницах, отданных самим сервером (в отчёте ключ добавляется только к запросам на свой адрес).
   Ответы запрещают встраивание страниц во фрейм; запрос больше 64 КБ отклоняется, недосланный — обрывается
   через 10 с.
3. Страница хода с журналом, затем `report.html`. «Показать в KiCad» — запрос к серверу: объекты по uuid
   (площадки, переходные, трассы, зоны) или компоненты по обозначению выделяются, KiCad приближает
   выделенное. «Проверить снова» (внизу справа) — к настройкам и новой проверке текущего состояния платы.
   Сервер завершается после 30 минут без обращений (идущая проверка доводится до конца).

Отчёт пишется в `<reports>/<имя платы>`. Перед новой проверкой там удаляются только файлы отчёта
(`report.html`, `findings.json`, `report.md`, `layers/*.png`) и только в папке с меткой `.dfm-report`,
которую создаёт плагин (или в папке, где, кроме файлов отчёта, ничего нет). Если `reports` по ошибке указывает,
например, на папку проектов и папка проекта совпала с именем платы, она не очищается — проверка
останавливается с сообщением. Проверка считается удачной, только если `dfm check` завершился с кодом 0 или 1
(1 — есть находки-ошибки) и создал новый `report.html`; иначе на странице хода — ошибка и журнал.

Отчёт, открытый просто как файл, кнопок «Показать в KiCad» не показывает — им нужен плагин.

## Если не работает

- Открылась страница «не удалось начать» — не включён сервер IPC API, не открыта плата или испорчен
  `config.json` плагина (причина — на странице).
- Профиль завода в списке недоступен («ошибка профиля») — его `.toml` не читается; причина — под списком.
- Кнопки нет — KiCad не видит папку плагина: путь в Настройки → Плагины, «Открыть папку плагинов».
- Ход проверки показывает ошибку Python — путь `python` в `config.json` должен вести к окружению
  с пакетом `dfm` (`python -m dfm --help` в нём работает).
- Приближение к выделенному использует внутреннее действие KiCad `common.Control.zoomFitSelection`;
  если в другой версии KiCad его нет, объекты выделяются без приближения.
